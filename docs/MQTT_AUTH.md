# MQTT Authentication Guide

> **Scope**: This document covers MQTT TLS configuration for **ESP32 LED sign devices only**. For general alert integration (scripts, services, applications), use the HTTP gateway instead. See `CLIENTNODE.md` for HTTP integration.

This guide covers username/password authentication for the Alert Manager MQTT broker.

## Overview

The Alert Manager MQTT broker uses **username/password authentication** for external connections (port 42690):

1. **Username/Password Authentication** - Credentials-based auth (**recommended for all devices**)
   - ✅ Works with ESP32/ESP8266 devices
   - ✅ Works with Windows/Linux applications
   - ✅ Easier debugging and troubleshooting
   - ✅ Lower memory footprint
   - ✅ Simpler configuration

~~2. **TLS Client Certificates**~~ (**Deprecated**)
   - ⚠️ Client certificates are no longer required
   - Use username/password instead for simpler configuration

**TLS encryption** is still enabled on port 42690 (server-side certificate only). Internal services (port 1883) use anonymous authentication and are only accessible within the Docker container network.

**QoS Level**: All gateways use **QoS 1** (at-least-once delivery) for reliable message delivery with ESP32-friendly overhead.

## ESP32 Compatibility

The Alert Manager MQTT broker is **optimized for ESP32 devices** with the following configurations:

### RSA Key Size: 2048-bit

**Why 2048-bit instead of 4096-bit?**
- ESP32 devices have **limited RAM** (typically 520KB total, ~200KB available for user code)
- ESP32 crypto hardware acceleration supports **up to 2048-bit RSA** efficiently
- 4096-bit RSA operations can take **10-30 seconds** per handshake or fail entirely due to memory constraints
- 2048-bit RSA provides **adequate security** for IoT devices while maintaining compatibility

All certificates generated by `tools/cert-manager.sh` use 2048-bit RSA keys by default.

### TLS Configuration

**Supported TLS Version:** TLSv1.2 (configured in mosquitto.conf)

**ESP32-Compatible Cipher Suites:**
1. **ECDHE-RSA-AES128-GCM-SHA256** (Recommended - hardware accelerated)
2. **ECDHE-RSA-AES256-GCM-SHA384** (Fallback)
3. **ECDHE-RSA-AES128-SHA256** (Legacy support)

These cipher suites are specifically chosen because:
- ESP32 has **hardware AES acceleration** (fast encryption/decryption)
- ECDHE provides **forward secrecy** (past sessions remain secure even if private key is compromised)
- GCM mode is **hardware accelerated** on ESP32 (better performance than CBC)

### Memory Requirements

**Minimum ESP32 configuration for TLS MQTT:**
- **Free heap:** At least 50KB before connection attempt
- **Stack size:** 8-16KB for MQTT task (depending on library)
- **Certificate storage:** ~2KB for CA certificate (use `PROGMEM` on Arduino)

### Common ESP32 TLS Issues

**"mbedtls_ssl_handshake returned -0x7200" (out of memory)**
- Solution: Increase heap by reducing buffer sizes, use PSRAM if available
- Check: `ESP.getFreeHeap()` before connecting (should be >50KB)

**"mbedtls_pk_parse_key returned -0x3f00" (invalid key)**
- Solution: Ensure certificate uses 2048-bit RSA (not 4096-bit)
- Regenerate certificates with `tools/cert-manager.sh` if needed

**Handshake timeout after 10-15 seconds**
- Cause: 4096-bit certificate or unsupported cipher suite
- Solution: Regenerate 2048-bit certificates and verify cipher suites

**"ssl_client returned -1" (generic failure)**
- Check: CA certificate matches server certificate
- Verify: `alert.d-t.pw` resolves to correct IP
- Test: `openssl s_client -connect alert.d-t.pw:42690 -CAfile ca.crt`

## Connection Ports

| Port | TLS | Authentication | Access |
|------|-----|----------------|--------|
| **1883** | No | Anonymous | Internal Docker network only |
| **42690** | Yes (TLS 1.2+) | Username/Password OR Client Cert | External devices/services |
| **9001** | No | Anonymous | WebSocket (browser clients) |

## Username/Password Authentication

### For ESP Devices and IoT Sensors

Username/password authentication is the easiest method for ESP8266/ESP32 devices and other IoT sensors that may have difficulty handling client certificates.

#### Prerequisites

- ESP device must support TLS/SSL (most ESP8266/ESP32 libraries do)
- Only the **CA certificate** is needed (not client certificate/key)
- MQTT library with username/password support (PubSubClient, AsyncMQTT, etc.)

#### Step 1: Create MQTT User

Use the `mqtt-auth-manager.sh` script to create a username/password:

```bash
# Interactive mode (prompts for password)
./tools/mqtt-auth-manager.sh add esp-kitchen

# Or provide password on command line (less secure)
./tools/mqtt-auth-manager.sh add esp-kitchen MySecurePassword123
```

The password is hashed using PBKDF2-SHA512 and stored in `data/mosquitto/config/passwd`.

#### Step 2: Configure Access Control

Edit `data/mosquitto/config/acl.conf` to grant the user access to topics.

**Zone-Specific LED Sign Pattern** (per mqttservernotes.txt):

```conf
# LED Sign device - zone-specific access
# Each device reads messages for its zone only and writes status telemetry
user ledsign_kitchen
topic read ledSign/kitchen/#
topic write ledSign/kitchen/rssi
topic write ledSign/kitchen/ip
topic write ledSign/kitchen/uptime
topic write ledSign/kitchen/memory

user ledsign_office
topic read ledSign/office/#
topic write ledSign/office/rssi
topic write ledSign/office/ip
topic write ledSign/office/uptime
topic write ledSign/office/memory
```

**Alert Manager Service User:**

```conf
# Internal service that publishes to all LED sign zones
user alert_manager
topic write ledSign/+/message
topic read ledSign/#
topic read alerts/service/status
```

**LED Status Topics:**

| Topic | Direction | Description |
|-------|-----------|-------------|
| `ledSign/{zone}/rssi` | Write | WiFi signal strength (dBm) |
| `ledSign/{zone}/ip` | Write | Device IP address |
| `ledSign/{zone}/uptime` | Write | Device uptime (seconds) |
| `ledSign/{zone}/memory` | Write | Free heap memory (bytes) |

#### Step 3: Restart MQTT Broker

```bash
docker-compose restart alert-mqtt-broker
```

Wait 5-10 seconds for the broker to restart and reload configuration.

#### Step 4: Configure ESP Device

##### Arduino/PlatformIO Example (PubSubClient)

```cpp
#include <WiFiClientSecure.h>
#include <PubSubClient.h>

// MQTT Configuration
const char* mqtt_server = "alert.d-t.pw";
const int mqtt_port = 42690;
const char* mqtt_user = "esp-kitchen";
const char* mqtt_password = "MySecurePassword123";

// CA Certificate (from data/certs/ca/ca.crt)
const char* ca_cert = R"EOF(
-----BEGIN CERTIFICATE-----
MIIFazCCA1OgAwIBAgIUQp6XKX7vN...
[rest of certificate]
-----END CERTIFICATE-----
)EOF";

WiFiClientSecure espClient;
PubSubClient client(espClient);

void setup() {
    Serial.begin(115200);

    // Connect to WiFi
    WiFi.begin("YourSSID", "YourPassword");
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }

    // Configure TLS with CA certificate only
    espClient.setCACert(ca_cert);

    // Set MQTT server
    client.setServer(mqtt_server, mqtt_port);

    // Connect to MQTT
    connectMQTT();
}

void connectMQTT() {
    while (!client.connected()) {
        Serial.println("Connecting to MQTT...");

        // Connect with username and password
        if (client.connect("esp-kitchen-01", mqtt_user, mqtt_password)) {
            Serial.println("Connected to MQTT broker");
        } else {
            Serial.print("MQTT connection failed, rc=");
            Serial.println(client.state());
            delay(5000);
        }
    }
}

void sendAlert() {
    String payload = "{\"timestamp\":" + String(time(nullptr)) +
                    ",\"level\":\"info\"," +
                    "\"category\":\"automation\"," +
                    "\"title\":\"Kitchen Sensor\"," +
                    "\"message\":\"Motion detected\"," +
                    "\"source\":\"esp-kitchen\"," +
                    "\"client\":\"home-automation\"}";

    client.publish("alerts/input", payload.c_str());
}

void loop() {
    if (!client.connected()) {
        connectMQTT();
    }
    client.loop();

    // Your sensor logic here
}
```

##### MicroPython Example (ESP8266/ESP32)

```python
import machine
import network
import time
from umqtt.simple import MQTTClient
import ussl

# MQTT Configuration
MQTT_SERVER = "alert.d-t.pw"
MQTT_PORT = 42690
MQTT_USER = "esp-kitchen"
MQTT_PASSWORD = "MySecurePassword123"
MQTT_CLIENT_ID = "esp-kitchen-01"

# CA Certificate (save to ca.crt file on ESP)
CA_CERT_FILE = "ca.crt"

# Connect to WiFi
sta_if = network.WLAN(network.STA_IF)
sta_if.active(True)
sta_if.connect("YourSSID", "YourPassword")
while not sta_if.isconnected():
    time.sleep(0.5)
print("WiFi Connected")

# Create MQTT client with TLS
client = MQTTClient(
    client_id=MQTT_CLIENT_ID,
    server=MQTT_SERVER,
    port=MQTT_PORT,
    user=MQTT_USER,
    password=MQTT_PASSWORD,
    ssl=True,
    ssl_params={'ca_certs': CA_CERT_FILE}
)

# Connect to broker
client.connect()
print("MQTT Connected")

# Send alert
payload = b'{"timestamp":1234567890,"level":"info","category":"automation","title":"Test","message":"Motion detected","source":"esp-kitchen"}'
client.publish(b"alerts/input", payload)

client.disconnect()
```

#### Troubleshooting ESP Connections

**Connection failed with rc=-2 (timeout)**
- Check firewall allows port 42690
- Verify ESP can reach `alert.d-t.pw` (ping test)
- Increase connection timeout in MQTT library

**Connection failed with rc=4 (bad credentials)**
- Verify username/password are correct
- Check user exists in ACL configuration
- Restart MQTT broker after ACL changes

**Connection failed with rc=5 (not authorized)**
- User exists but lacks ACL permissions
- Check `acl.conf` has rules for your username
- Restart broker to reload ACL

**TLS handshake failed**
- CA certificate may be incorrect or expired
- ESP may not support required TLS cipher suites
- Try updating ESP TLS/SSL library

**Out of memory errors**
- CA certificate is large (~1-2KB) - use PROGMEM on Arduino
- Reduce MQTT buffer sizes in library configuration
- Use shorter topic names and smaller payloads

## Certificate-Based Authentication

### For Secure Services and Integrations

Certificate authentication provides stronger security through mutual TLS. Each client has a unique certificate signed by the CA.

#### Step 1: Generate Client Certificate

Use the `cert-manager.sh` script:

```bash
# Create certificate for a device (10 year validity)
./tools/cert-manager.sh create-client my-service device

# Create certificate for a service integration (5 year validity)
./tools/cert-manager.sh create-client my-api-client service
```

This creates:
- `data/certs/clients/my-service-bundle.tar.gz` - Distribution bundle
- Contains: ca.crt, client.crt, client.key, config files, test scripts

#### Step 2: Extract Certificate Bundle

```bash
cd data/certs/clients
tar -xzf my-service-bundle.tar.gz
cd my-service
```

#### Step 3: Configure Access Control

Edit `data/mosquitto/config/acl.conf`:

```conf
user my-service
topic write alerts/input
topic read alerts/service/status
```

When using client certificates, the username is extracted from the certificate Common Name (CN).

#### Step 4: Test Connection

Use the included test script:

```bash
cd data/certs/clients/my-service
./test-connection.sh
```

Or manually with mosquitto_pub:

```bash
mosquitto_pub \
    -h alert.d-t.pw \
    -p 42690 \
    --cafile ca.crt \
    --cert client.crt \
    --key client.key \
    -t alerts/input \
    -m '{"timestamp":1234567890,"level":"info","category":"system","title":"Test","message":"Hello","source":"my-service"}'
```

#### Python Example with Certificates

```python
import paho.mqtt.client as mqtt
import ssl
import json
import time

# MQTT Configuration
MQTT_HOST = "alert.d-t.pw"
MQTT_PORT = 42690
CA_CERT = "ca.crt"
CLIENT_CERT = "client.crt"
CLIENT_KEY = "client.key"

def on_connect(client, userdata, flags, rc):
    if rc == 0:
        print("Connected to MQTT broker")
        client.subscribe("alerts/service/status")
    else:
        print(f"Connection failed with code {rc}")

def on_message(client, userdata, msg):
    print(f"Received: {msg.topic} -> {msg.payload.decode()}")

# Create MQTT client
client = mqtt.Client(client_id="my-service-01")
client.on_connect = on_connect
client.on_message = on_message

# Configure TLS with client certificate
client.tls_set(
    ca_certs=CA_CERT,
    certfile=CLIENT_CERT,
    keyfile=CLIENT_KEY,
    cert_reqs=ssl.CERT_REQUIRED,
    tls_version=ssl.PROTOCOL_TLSv1_2
)

# Connect to broker
client.connect(MQTT_HOST, MQTT_PORT, 60)
client.loop_start()

# Send alert
alert = {
    "timestamp": int(time.time()),
    "level": "info",
    "category": "system",
    "title": "Service Started",
    "message": "My service has started successfully",
    "source": "my-service"
}

client.publish("alerts/input", json.dumps(alert))

time.sleep(2)
client.loop_stop()
client.disconnect()
```

## Security Best Practices

### Password Management

1. **Use strong passwords** - At least 16 characters, mixed case, numbers, symbols
2. **Never commit passwords** - Keep `.env` and password files out of git
3. **Rotate passwords regularly** - Change passwords every 6-12 months
4. **Unique passwords per device** - Don't reuse passwords across devices

### Certificate Management

1. **Keep private keys secure** - Never share client.key files
2. **Use appropriate validity periods** - Device (10yr), Service (5yr), Client (2yr), Temporary (30d)
3. **Revoke compromised certificates** - Use `cert-manager.sh revoke-client` if compromised
4. **Monitor certificate expiry** - Set reminders before certificates expire

### Network Security

1. **Use TLS for all external connections** - Never disable TLS on port 42690
2. **Limit ACL permissions** - Grant minimum required access per user
3. **Monitor MQTT logs** - Check `data/logs/ops/mosquitto.log` for suspicious activity
4. **Firewall external port** - Only allow trusted IPs to access port 42690 if possible

### ESP Device Security

1. **Store credentials securely** - Use ESP SPIFFS encryption or secure elements
2. **Update ESP libraries** - Keep TLS/SSL libraries up to date
3. **Handle reconnection properly** - Implement exponential backoff
4. **Validate server certificate** - Always verify CA certificate

## Configuration Files

### Password File
**Location:** `data/mosquitto/config/passwd`
**Format:** `username:$7$101$hash...`
**Management:** Use `tools/mqtt-auth-manager.sh` (do not edit manually)

### ACL File
**Location:** `data/mosquitto/config/acl.conf`
**Format:** Plain text, one rule per line
**Management:** Edit directly, restart broker to apply

### Mosquitto Configuration
**Location:** `data/mosquitto/config/mosquitto.conf`
**Format:** INI-style configuration
**Management:** Edit carefully, restart broker to apply

## Common Issues

### "Connection Refused" Errors
- Check broker is running: `docker-compose ps alert-mqtt-broker`
- Verify port 42690 is accessible: `telnet alert.d-t.pw 42690`
- Check firewall rules on server

### "Authentication Failed" Errors
- Verify username/password are correct
- Check user exists in password file: `./tools/mqtt-auth-manager.sh list`
- Ensure broker was restarted after adding user

### "Not Authorized" Errors
- User authenticated but lacks ACL permissions
- Check `acl.conf` has rules for your username
- Verify broker restarted after ACL changes

### TLS/Certificate Errors
- Verify CA certificate is correct and not expired
- Check certificate format (PEM, not DER)
- Ensure certificate includes full chain if needed
